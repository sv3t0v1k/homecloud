# Отчёты агентов

Рабочая зона для структурированных отчётов соседних агентов (схема «тимлид-чат + исполнители»). Отчёт агента — **не доказательство**: тимлид сверяет его с фактическим `git diff`, тестами и инвариантами проекта перед принятием.

## Правила

1. Один отчёт — один файл: `YYYYMMDD-<короткое-имя-задачи>.md`.
2. Агент заполняет шаблон ниже и обязан указать известные пробелы честно — скрытое ограничение хуже отсутствующего отчёта.
3. Отчёт не является qualification evidence: для закрытия квалификации требуется отдельное evidence по правилам [../README.md](../README.md).
4. Запрещено фиксировать в отчёте секреты, credentials, raw session data.
5. Если задача затронула `deploy/`, CI-конфиги или trust anchors — это квалифицируется по security policy v2, отчёт помечается `ТРЕБУЕТ НЕЗАВИСИМОГО REVIEW`.

## Шаблон

```markdown
# <Название задачи>

- Дата: YYYY-MM-DD
- Агент: <модель/роль, например Kimi 3.1 Высокий — backend>
- Ветка: <имя ветки>
- HEAD на момент отчёта: <полный SHA>
- Статус: ГОТОВО К ПРОВЕРКЕ | ЧЕРНОВИК | ЗАБЛОКИРОВАН

## Что сделано
<пункты по факту, со ссылками на файлы>

## Проверки
- <команды и результаты: тесты, lint, build — с цифрами>

## Состав изменений
- <ветка, коммиты: SHA — описание>

## Известные ограничения и пробелы
<что НЕ проверено, что осталось за скобками>

## Затронутые критические области
<deploy/, CI, trust anchors, storage, migrations — или «нет»>
```
