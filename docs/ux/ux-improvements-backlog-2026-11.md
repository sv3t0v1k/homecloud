# HomeCloud — UX/UI улучшения: утверждённый backlog

Дата: 2026-11-23. Статус: **ожидает решения владельца о старте реализации**.

Источник: readonly-аудит frontend/UX/UI от 2026-11-23. Реализация не начата;
каждая фаза стартует только по прямому указанию владельца (AGENTS.md, правило 2).

## Исключено решением владельца

- Светлая тема (переключатель, раздел «Оформление»).
- «Быстрый доступ»: раздел «Недавние» и «Избранное».

Эти направления не предлагать повторно без нового решения владельца.

## Фаза U1 — Быстрые улучшения оболочки (quick wins)

Только frontend, малый объём, изолированные файлы.

1. **Favicon, `theme-color`, apple-touch-icon, meta description** в
   `frontend/index.html` + ассеты в `frontend/public/`.
2. **Web App Manifest** (`manifest.webmanifest`, иконки) — установка на
   домашний экран как app.
3. **Страница 404** в стиле `empty-state`: иконка, бренд, ссылка «К моим файлам»
   (`frontend/src/App.tsx`).
4. **Аватар с инициалами**: цвет от имени пользователя в топбаре и в профиле
   вместо одинаковой иконки `user`.
5. **Индикатор квоты**: тонкий индикатор заполнения хранилища (топбар или
   предупреждение при загрузке сверх ~85%); данные уже отдаёт `getStorageInfo`.
6. **Глобальный offline-баннер** «Нет соединения»: слушатели `online`/`offline`,
   единая плашка вместо разрозненных ошибок операций.
7. **Схлопывание breadcrumbs на мобильном**: «Мои файлы / … / Текущая».
8. **Чистка мёртвого CSS** в `styles/base-and-legacy.css`: удалить стили
   убранного сайдбара (`.sidebar*`, `.nav-item`, `.sidebar-drawer`,
   `.mobile-menu`, `.drawer-*`), дубли `.upload-manager`/`.files-toolbar`,
   протухший fallback `var(--accent, #88bda1)` (старый оттенок), неиспользуемый
   `.directory-search` — сверить с живым кодом перед удалением каждого блока.

Acceptance: production build PASS, lint PASS, существующие frontend-тесты PASS;
визуальная проверка на desktop и ≤560px.

## Фаза U2 — Сортировка и фильтр в папке

1. Кликабельные заголовки колонок (Название / Тип / Размер / Изменено) со
   стрелкой направления и `aria-sort`; состояние в URL или на сессию.
2. Клиентская сортировка текущей страницы папки (серверный порядок не меняем —
   API-контракты не трогаем).
3. Локальный фильтр по имени в текущей папке (поле над таблицей; класс
   `.directory-search` либо реанимировать, либо заменить).

Acceptance: тесты на сортировку/фильтр (vitest), клавиатурный доступ к
заголовкам, скринридер объявляет направление сортировки.

## Фаза U3 — Toast-стек и undo

1. Единая система уведомлений: автозакрытие, стек, `role="status"`,
   reduced-motion-совместимые анимации, не перекрывает trash-launcher и
   upload-dock.
2. Перевести на него: «Скачивание передано браузеру», «ZIP передан браузеру»,
   успешные операции переименования/перемещения/копирования.
3. **Undo для перемещения в корзину**: тост «Отменить» (5–7 секунд), вызывает
   существующий `restoreTrashItem`. Подтверждающий диалог остаётся; undo —
   дополнение, не замена.

Acceptance: тесты на очередь тостов и undo-восстановление; позиционирование на
мобильном не пересекается с selection-dock.

## Фаза U4 — Предпросмотр

1. Листание файлов стрелками ←/→ и кнопками в `PreviewModal` (в пределах
   текущей папки; счётчик «3 из 24»).
2. Зум изображений: колесо мыши / двойной тап / кнопки, сброс по Esc уже есть
   у диалога — не конфликтовать.
3. PDF-предпросмотр: вариант A — `<iframe>`/`<embed>` на существующий
   download-endpoint; вариант B — pdf.js. Решение по transport безопасности
   принять до реализации (Phase 13 явно ограничивала browser download
   безопасным transport).
4. Аудио-предпросмотр (`<audio>`) — по остаточному принципу фазы.

Acceptance: навигация не теряет фокус, object URL освобождаются при листании,
тесты на переключение элементов.

## Фаза U5 — Клавиатурная навигация по файлам

1. Стрелки ↑/↓/←/→ по строкам (list) и сетке (grid), Home/End, PageUp/PageDown.
2. Ctrl/Cmd+A — выбрать всё в текущей папке; Esc — снять выделение.
3. Delete/Backspace — в корзину (с существующим подтверждением);
   F2 — переименовать выбранное; Enter — открыть.
4. Экран справки по шорткатам (клавиша `?`), рендерится из единого реестра
   шорткатов.

Acceptance: шорткаты не срабатывают в input/textarea/диалогах (есть готовый
паттерн проверки target в Navbar); тесты на реестр и блокировки.

## Фаза U6 — Внутренний drag-and-drop перемещения

1. Перетаскивание файла/папки на строку папки, на карточку в grid и на элемент
   breadcrumbs → существующий `moveFile`/`moveFolder`.
2. Визуальные состояния цели (hover-подсветка, запрет на собственный поддерево —
   сервер уже защищает от циклов, UI показывает «нельзя»).
3. Мультивыбор перетаскивается группой.

Acceptance: не ломает существующий drop загрузки из системы (разные типы
dataTransfer); тесты на валидацию цели; отключение на touch-устройствах.

## Фаза U7 — Контекстное меню у курсора

1. Заменить приём «программный клик по кнопке ⋯» на поповер у точки клика
   (позиционирование с учётом краёв экрана).
2. Сохранить единый источник пунктов меню с ActionMenu (без дублирования
   действий), клавиатурная навигация и Escape — как в ActionMenu.

Acceptance: меню не выходит за вьюпорт, фокус возвращается в строку,
существующие тесты ActionMenu продолжают проходить.

## Фаза U8 — Мелочи интерфейса

1. QR-код в `ShareDialog` (показ ссылки на телефон); генерация на клиенте,
   без внешних сервисов.
2. Дерево-диалог выбора папки назначения вместо плоского select в
   «Переместить/Копировать» при большом числе папок.
3. i18n: вынос строк в словарь (без добавления второго языка) — подготовка,
   выполняется последней, чтобы не конфликтовать с U1–U7 по текстам.

## Общие ограничения для всех фаз

- Не менять API-контракты backend без отдельного решения (ROADMAP: пагинация и
  порядок списков уже DEFERRED по этой причине).
- Сохранять текущий уровень a11y: skip-link, focus management, reduced-motion.
- Каждая фаза завершается: targeted tests → полный набор frontend-тестов →
  lint → build; результат фиксируется commit на русском языке.
- Не переоткрывать исключённые направления (светлая тема, быстрый доступ).
